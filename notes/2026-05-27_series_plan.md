# Content Agent 实践系列内容计划

日期：2026-05-27

## 系列定位

这是一个记录自己实践 AI Agent 的系列，不走“炫技发布会”路线，而是走真实开发日志路线：

> 我从一个内容生成脚本开始，逐步把它改造成一个具备 Agent 特征的内容创作系统。

项目当前最适合的表达：

> 一个内容创作 Agent 原型：从笔记输入开始，经历研究、写作、审稿、修改、入队，逐步加入工具、记忆和自动化触发。

注意不要一开始就说“完全自主 Agent”。更可信的说法是：它正在从内容生成工具演进为 Agent。

## 目标受众

- 想理解 AI Agent 但还没有实战的人
- 会写一点代码，想做自己的自动化工具的人
- 对内容自动化、个人 IP、公众号/抖音/小红书运营感兴趣的人
- 关注“AI 怎么真实改变工作流”的普通读者

## 主线叙事

1. 最初只是一个脚本：输入技术笔记，输出平台文案。
2. 后来发现单次生成不够，需要质量检查和重试。
3. 再后来把角色拆开：Writer、Editor、Researcher。
4. 然后加入 Orchestrator，让流程可控。
5. 继续加入工具系统和 ReAct，让 Agent 能思考、行动、观察。
6. 最后慢慢加入记忆、队列、选题、排期和发布审核门。

核心矛盾：

> Agent 不是一次性生成答案，而是围绕目标持续推进任务。

## 公众号文章规划

### 第 1 篇：我为什么要做一个 Content Agent

核心问题：为什么需要这个项目？

内容要点：

- 自己有很多技术学习笔记，但转成公众号/抖音/小红书很耗时间。
- 一开始只想做一个“多平台文案改写工具”。
- 后来发现内容生产不是一次生成，而是一个流程：选题、研究、写作、审稿、配图、排期、发布。
- 这天然适合用 Agent 思路重构。

标题备选：

- 《我为什么要做一个内容创作 Agent》
- 《从写笔记到发内容，我想让 AI 接管哪些重复劳动》

抖音切法：

- 开头钩子：我不是想做一个聊天机器人，我想做一个能帮我发内容的 AI。
- 画面：笔记文件、三平台输出、流程图。

### 第 2 篇：第一个版本其实不是 Agent，只是内容生成工具

核心问题：工具和 Agent 的区别是什么？

内容要点：

- 最初版本：输入笔记，调用 LLM，输出三平台内容。
- 它能用，但没有自主性。
- 用户决定什么时候开始、生成什么、下一步做什么。
- 这更像工具，不是 Agent。
- 借此解释工具和 Agent 的区别。

标题备选：

- 《第一个版本不是 Agent，只是一个 AI 工具》
- 《别急着叫 Agent：先把工具做好》

抖音切法：

- 开头钩子：很多人把“套壳调用大模型”叫 Agent，其实还差很远。
- 画面：工具 vs Agent 对比表。

### 第 3 篇：拆出 Writer 和 Editor，开始有 Agent 味道

核心问题：为什么要拆角色？

内容要点：

- 单次生成的问题：质量不稳定，平台风格不稳定。
- 拆出 WriterAgent 负责写。
- 拆出 EditorAgent 负责审。
- 加入“写稿 → 审稿 → 修改”的循环。
- 解释这为什么比单次 prompt 更接近 Agent。

标题备选：

- 《我给 AI 加了一个编辑，它终于不再一稿到底》
- 《Writer + Editor：内容 Agent 的第一个闭环》

抖音切法：

- 开头钩子：真正让我感觉它像 Agent 的，不是写得快，而是它会被审稿。
- 画面：Writer/Editor 循环图。

### 第 4 篇：Orchestrator：Agent 不是越自由越好

核心问题：为什么需要调度器？

内容要点：

- Orchestrator 是纯 Python 调度器，不是 LLM。
- 它决定步骤：research、write、edit。
- 它限制最大修改轮数和最大 LLM 调用次数。
- 它负责失败熔断和 human review。
- Agent 系统里，确定性的控制层很重要。

标题备选：

- 《Agent 不是越自由越好，我给它加了调度器》
- 《Orchestrator：让 AI 办事不失控》

抖音切法：

- 开头钩子：做 Agent 最大的误区，是把所有决策都交给大模型。
- 画面：LLM 大脑 + Python 控制器。

### 第 5 篇：ReAct：让 Agent 学会思考、行动和观察

核心问题：ReAct 到底是什么？

内容要点：

- 介绍 Thought → Action → Observation。
- Agent 先判断是否需要搜索。
- 再调用 generate / evaluate 等工具。
- 评估不通过时反思修改。
- 也要坦诚当前项目里的 ReAct 还需要继续补完整闭环。

标题备选：

- 《我给 Content Agent 加了 ReAct 循环》
- 《AI Agent 的核心动作：想一下，做一步，看结果》

抖音切法：

- 开头钩子：AI Agent 最重要的不是会说，而是会“想一步、做一步、看结果”。
- 画面：Thought / Action / Observation 三段动画。

### 第 6 篇：工具系统：Agent 能做事，靠的是工具

核心问题：Agent 如何从“会说”变成“会做”？

内容要点：

- 工具包括 search、browse、read、generate、evaluate、publish、rag、analyze。
- 每个工具是一个可控边界。
- 高风险工具需要审核门。
- 工具层不能硬编码本机路径，后续需要整理。

标题备选：

- 《Agent 会办事，不是因为模型更神，而是因为它有工具》
- 《我给 Agent 接了 8 个工具》

抖音切法：

- 开头钩子：没有工具的 Agent，只是一个会装作很忙的聊天机器人。
- 画面：工具箱隐喻。

### 第 7 篇：从按钮工具到自动化 Agent

核心问题：什么时候开始像真正的 Agent？

内容要点：

- AgentController 监听笔记。
- TopicExecutor 执行选题。
- PublishQueue 保存待发内容。
- StyleProfile 记录风格样本。
- 从“用户点击生成”变成“系统发现新笔记后自动处理”。

标题备选：

- 《当它开始自己扫描笔记，我才觉得它像 Agent》
- 《从手动点击，到自动入队》

抖音切法：

- 开头钩子：当我不再点按钮，它自己发现新笔记并生成内容时，Agent 味道出来了。
- 画面：inbox → task → queue。

### 第 8 篇：我踩过的坑和下一步重构

核心问题：真实项目哪里最容易乱？

内容要点：

- 一开始脚本快速迭代，后来架构开始散。
- 旧链路和新链路并存。
- ModelConfig 重复。
- ReAct 闭环不完整。
- RAG 工具漂移。
- 下一步暂停加功能，先做架构收口。

标题备选：

- 《做 Agent 项目最容易踩的坑：功能越来越多，架构越来越散》
- 《暂停加功能，我要先整理这个 Agent 项目》

抖音切法：

- 开头钩子：做 Agent 最真实的坑，不是模型不会用，而是你自己的项目会先乱。
- 画面：混乱代码结构 → 收口路线图。

### 加餐篇：搜索资料把用户主题覆盖了

核心问题：Agent 调工具之后，为什么反而更容易跑题？

真实案例：

- 用户输入：“帮我写一篇给小白介绍 AI Agent 的微信公众号文章”。
- 系统先搜索资料，再进入 Planner。
- Planner 二次搜索时把整段 Markdown 笔记当成查询词。
- 生成阶段又用 `context.research_report or raw_notes`，导致只要有搜索结果，就把原始主题覆盖掉。
- 最终 Writer 收到的“笔记内容”变成了 Google 搜索结果，于是文章跑到了 Google 搜索主题。

核心教训：

> 工具结果不能替代用户目标，只能作为上下文补充。

可展开的技术点：

- 用户目标、原始笔记、搜索资料要分层保存。
- Planner 搜索应该提取主题，而不是拿整段上下文搜索。
- Writer 输入应该是“原始笔记 + 补充研究资料”，不能二选一覆盖。
- Agent 数据流要可观测：日志里要能看到每一层输入输出。
- 这是典型的上下文污染问题，不是模型能力问题。

标题备选：

- 《我做 Agent 踩的第一个坑：搜索资料把用户主题覆盖了》
- 《Agent 为什么会跑题？一次真实 Bug 复盘》
- 《工具结果不是用户目标：我修了一个 Agent 上下文污染问题》

抖音切法：

- 开头钩子：我让 Agent 写 AI Agent，结果它写成了 Google 搜索。
- 画面：用户输入 → 搜索资料 → Planner → Writer 的数据流。
- 关键反转：模型没乱写，是我把错误上下文喂给了它。
- 结尾判断：做 Agent，最重要的不是多接工具，而是别让工具结果污染目标。

## 抖音视频固定模板

每条视频建议 60-120 秒。

结构：

1. 前 3 秒：一句强钩子。
2. 10 秒：说明真实问题。
3. 30-60 秒：展示一个具体实现或流程。
4. 10 秒：总结一个可记住的判断。
5. 结尾：引导下一期。

固定口播句式：

- “我不是在做一个聊天机器人，我是在做一个能帮我推进内容生产的 Agent。”
- “这个版本还不完美，但它已经从工具开始长出 Agent 的形态。”
- “Agent 不是一次性生成答案，而是围绕目标持续推进任务。”
- “真正重要的不是模型多强，而是目标、工具、记忆、反馈怎么组织起来。”

## 视觉生产流程

当前已经跑通的抖音视频流程：

```text
主题/文案
→ 生成中文手绘技术 PPT 页面图
→ 写口播稿
→ edge-tts 生成中文语音
→ HyperFrames 串图、加字幕、加转场
→ FFmpeg 渲染 MP4
→ 抽帧检查
→ 生成竖版封面
→ 发布文案和话题
```

推荐默认风格：

- 中文手绘技术解释风
- 近白纸张背景
- 细线手绘物件
- 少量 pastel 标签
- 大留白
- 字幕用 HyperFrames 加，避免图片内中文不稳定

## 已验证素材形式

### 1. 图片生成版

优点：

- 手绘感强
- 有作者感
- 适合抖音/公众号封面和科普内容

缺点：

- 图片内中文有不稳定风险
- 后期改文案成本高

### 2. HTML 生成版

优点：

- 文字准确
- 易修改
- 文件小
- 适合批量、多语言、多版本

缺点：

- 手绘质感弱
- 更像课件

### 3. Hybrid 版

方向成立：

- imagegen 生成无文字手绘底图
- HTML 叠加真实文字、标签、字幕

注意：

- 底图不要生成空标签框，否则 HTML 标签容易错位。
- 最好让底图只画物件和连接线，所有标签框和文字由 HTML 生成。

## 系列发布建议

- 每篇 1500-2500 字。
- 以代码片段、架构图、真实取舍为主。
- 不要写成工具教程，要写成“实践复盘”。

抖音：

- 每期聚焦一个概念。
- 多用流程图、对比图、执行轨迹。
- 不要堆代码细节，代码只作为可信背书。

- 可以发“开发日志卡片”。

- 标题要更口语化，例如“我终于搞懂 Agent 和工具的区别了”。
