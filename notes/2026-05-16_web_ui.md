# Web UI 实现记录

## 背景/需求

Roadmap 最后一个待办：Web UI。目标是让不喜欢命令行的用户也能使用 content-agent，同时为未来可能的内容变现（如提供 SaaS 服务）留下扩展点。

## 技术选型

| 方案 | 优点 | 缺点 | 适合场景 |
|-------|------|------|---------|
| **Gradio** | 极简、几行代码、支持文件上传、内置复制按钮 | 界面自定义程度有限 | 内部工具/原型/演示 |
| Streamlit | 更灵活、社区更大 | 略重、性能差一些 | 数据应用 |
| Flask + 前端 | 完全自定义 | 工作量大 | 正式产品 |

选择 **Gradio**：对于“输入笔记 → 选平台 → 点生成 → 看结果”这种简单交互，Gradio 是最低成本方案。

## 核心实现

### `web_ui.py` 结构

```
Gradio Blocks
├── 标题区
├── 输入区（左侧 Column）
│   ├── Textbox 粘贴笔记
│   ├── File 上传文件
│   └── 配置区（Group）
│       ├── CheckboxGroup 平台选择
│       ├── Checkbox 搜索增强开关
│       └── Dropdown 搜索引擎
├── 输出区（右侧 Column）
│   └── Tabs
│       ├── Tab 小红书
│       ├── Tab 公众号
│       └── Tab 抖音
└── 事件绑定（generate_btn.click → generate_content）
```

### `generate_content()` 处理函数

核心逻辑与 CLI 版相同，但适配 Gradio 的输入输出格式：

```python
def generate_content(note_text, note_file, platforms, enable_research, search_engine, progress=gr.Progress()):
    # 1. 读取输入（文本或文件）
    # 2. 解析平台
    # 3. 初始化 Agent（带进度条）
    # 4. 搜索增强（可选）
    # 5. 生成 + 质检（带进度条）
    # 6. 返回三平台文案 + 状态消息
```

**关键细节**：
- 使用 `gr.Progress()` 显示生成进度（初始化 10% → 搜索 20% → 生成 30% → 质检 45~75% → 整理 90% → 完成 100%）
- Agent 实例缓存（全局变量 `_agent`），避免每次点击都重新初始化
- 文件上传使用 Gradio 的 `gr.File`，返回的是 tempfile 路径
- 每个输出文本框开启 `show_copy_button=True`，一键复制

### 界面布局

使用 Gradio 的 `Soft` 主题，左右分栏布局：
- 左侧：输入 + 配置（占 1/2）
- 右侧：输出 Tab（占 1/2）

## 踩坑记录

1. **Gradio 安装后导入失败**：环境里 numpy 有兼容性问题（`ImportError: Error importing numpy: you should not try to import numpy from its source directory`）。这是测试环境的特殊问题，正常用户环境不会遇到。

2. **File 组件返回值**：Gradio 的 `gr.File` 输入在处理函数中接收的是文件路径（字符串），不是文件对象。直接 `open(note_file, "r")` 即可。

3. **Agent 缓存**：首次点击生成时初始化 Agent 需要几秒，之后复用缓存实例，响应更快。

4. **Gradio 4.44.1 + huggingface_hub 1.8.0 不兼容**（2025-05-16 修复）
   - 现象：`cannot import name 'HfFolder' from 'huggingface_hub'`
   - 原因：gradio 4.44.1（Python 3.9 最高版本）依赖的 `HfFolder` 在 huggingface_hub 1.8.0 中被移除
   - 修复：`pip install 'huggingface_hub==0.25.2'`

5. **gradio_client 1.3.0 bool schema bug**（2025-05-16 修复）
   - 现象：`TypeError: argument of type 'bool' is not iterable` / `AttributeError: 'bool' object has no attribute 'get'`
   - 原因：gradio_client 1.3.0 的 `_json_schema_to_python_type()` 在生成 API 文档时，某些组件的 `additionalProperties` 是 bool 值，但代码只处理了 dict 类型
   - 修复：给 `gradio_client/utils.py` 打补丁（两处）
     - `get_type()`: 开头加 `if not isinstance(schema, dict): return "object" if schema else "None"`
     - `_json_schema_to_python_type()`: 开头加 `if not isinstance(schema, dict): return "Any"`

6. **gradio localhost 检测失败**（2025-05-16 修复）
   - 现象：`ValueError: When localhost is not accessible...`
   - 原因：代理环境导致 gradio 无法通过 requests 访问 `127.0.0.1:7860` 自检
   - 修复：启动时设置环境变量 `no_proxy=127.0.0.1,localhost`，`launch()` 加 `share=False, inbrowser=False`

## 使用方法

```bash
# 安装依赖
pip install gradio

# 启动（如果有代理环境，加 no_proxy 避免 localhost 检测失败）
no_proxy=127.0.0.1,localhost python web_ui.py

# 打开浏览器访问 http://127.0.0.1:7860
```
