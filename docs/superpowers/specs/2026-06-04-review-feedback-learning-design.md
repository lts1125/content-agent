# 审核反馈学习设计

## 背景

当前项目已经具备审核面板、历史任务、引用透明、公众号偏好和发布状态回写。下一步需要让系统从用户的审核动作中学习，但不能因为一次临时选择就永久改变写作风格。

本阶段采用保守学习：记录用户在审核面板里的行为，沉淀为可解释的弱项信号和候选偏好，不自动覆盖显式偏好。

## 目标

- 记录用户对审核面板的关键决策：采纳修改、忽略建议、强行通过。
- 从失败维度和用户选择中提取弱项信号，用于后续生成时的轻量提醒。
- 避免记忆污染：只有高置信度或用户明确确认的内容才写入长期偏好。
- 在页面上让用户看见系统学到了什么，便于撤销或忽略。

## 非目标

- 不做自动 A/B 测试。
- 不自动改变 `gzh_default_style`、`gzh_target_reader` 等显式偏好。
- 不引入新的多用户权限系统。
- 不重新设计审核面板 UI，只在现有按钮流程里接入反馈记录。

## 方案

### 反馈事件

新增一层轻量反馈事件，来源于审核按钮：

| 用户动作 | 事件类型 | 含义 |
| --- | --- | --- |
| 按建议修改 | `revise` | 用户认可审核建议，说明这些弱项值得改 |
| 忽略建议 | `ignore` | 用户认为某些未通过项不重要 |
| 强行通过 | `force_publish` | 用户接受当前版本，审核标准可能过严或任务有特殊语境 |

每个事件记录：

- `task_id`
- `decision`
- `platforms`
- `overall`
- `items`：维度、分数、建议、是否被忽略
- `created_at`

### 学习规则

第一版只做确定性规则，不调用模型推断：

1. 用户点击“按建议修改”
   - 未通过且未忽略的维度计入弱项。
   - 例如公众号可读性低，多次出现后将 `readability` 加入 `weak_dimensions`。

2. 用户点击“忽略建议”
   - 被忽略的维度计入“低优先级审核项”统计。
   - 不立刻删除偏好，只在展示中提示“你经常忽略某项检查”。

3. 用户点击“强行通过”
   - 记录为人工接受。
   - 不更新长期偏好，避免系统误判为“低质量也可以”。

### 写入偏好策略

长期偏好只允许两种来源：

- 显式设置：用户通过 `#!pref` 或页面控件保存。
- 高置信度弱项：同一维度在最近 5 次审核事件中至少 3 次被采纳修改。

第一版只自动更新 `weak_dimensions`，并保留现有显式偏好优先级。

### 页面展示

在现有“当前默认”或“记忆与历史入口”附近增加一段轻量摘要：

```text
审核反馈：
- 最近常采纳修改：可读性、公众号结构
- 最近常忽略：代码示例不足
```

如果没有反馈事件，显示“暂无审核反馈”。

### 数据存储

优先复用现有 `review_panels` / `review_items` 表：

- `review_panels.user_decision` 已能记录最终决策。
- `review_items.ignored` 已能记录被忽略项。

为减少迁移风险，第一版不新增表。新增查询和学习函数，从现有审核表聚合：

- `list_review_feedback(limit=20)`
- `summarize_review_feedback(limit=20)`
- `learn_preferences_from_review_feedback(memory, limit=20)`

如果后续需要更细的反馈来源，再单独加 `feedback_events` 表。

## 数据流

```text
审核面板生成
  -> 用户点击审核按钮
  -> ReviewManager.apply_user_decision 更新 panel
  -> save_review_panel 持久化 user_decision / ignored
  -> 反馈学习器聚合最近审核记录
  -> 高置信度弱项写入 weak_dimensions
  -> UI 刷新当前偏好和审核反馈摘要
```

## 错误处理

- 反馈学习失败不影响生成、修改或发布。
- 审核表为空时返回空摘要。
- 偏好写入失败时只在日志中提示，不打断用户流程。
- 读取旧审核记录缺字段时跳过该条。

## 测试

- `ReviewManager.apply_user_decision` 后可持久化 `user_decision` 和 `ignored`。
- 反馈摘要能正确区分“常采纳修改”和“常忽略”。
- 同一弱项达到阈值后写入 `weak_dimensions`。
- 强行通过不会自动更新 `weak_dimensions`。
- UI 配置仍能生成，审核按钮输出数量不变。

## 验收标准

- 用户点击审核按钮后，刷新页面仍能看到对应反馈摘要。
- 连续多次采纳同一类修改后，生成约束中出现该弱项提醒。
- 忽略建议和强行通过不会直接污染公众号风格偏好。
- 所有现有审核面板测试和 chat UI 测试通过。
