# Eval Phase 2 设计文档

> 多维度打分优化 + 规则检查完善 + 成本统计

---

## 1. 多维度打分优化

### 当前问题
- LLM 一次打 4 个维度分，可能互相干扰
- 缺少热点匹配度、平台适配度评估

### 优化方案
- 每个维度单独评估（5 个独立 prompt）
- 新增维度：热点匹配度、平台适配度

### 评估维度

| 维度 | 说明 | 评估方式 |
|------|------|---------|
| 相关性 | 内容与主题的相关程度 | LLM 打分 1-10 |
| 可读性 | 语言流畅，结构清晰 | LLM 打分 1-10 |
| 原创性 | 有独特见解 | LLM 打分 1-10 |
| 实用性 | 读者获得实际价值 | LLM 打分 1-10 |
| 热点匹配 | 内容与热点的相关度（热点驱动时） | LLM 打分 1-10 |
| 平台适配 | 是否符合平台风格 | LLM 打分 1-10 |

---

## 2. 规则检查完善

### 当前
- 字数、敏感词、链接

### 新增
- 标题长度（公众号 20-30 字，小红书 15-20 字）
- 段落数（公众号 5-10 段，小红书 3-5 段）
- emoji 数量（小红书 5-10 个）
- 标签数量（小红书 5-8 个，公众号 3-5 个）
- 图片占位符数量

---

## 3. 成本统计

| 指标 | 说明 |
|------|------|
| prompt_tokens | 输入 token 数 |
| completion_tokens | 输出 token 数 |
| total_tokens | 总 token 数 |
| latency_ms | 生成耗时 |
| eval_latency_ms | 评估耗时 |
| model | 使用的模型 |
| eval_model | 评估用的模型 |

---

## 4. 实施步骤

1. 修改 LLMJudge：支持单维度评估
2. 修改 ContentEvaluator：逐个维度评估，汇总分数
3. 完善规则检查：新增平台特定规则
4. 测试验证：跑一篇内容，看各维度分数是否合理
