用3行代码搭建你的第一个 AI Agent：一个下班后做副业的内容改写助手

> 下班后的程序员能做什么副业？做自己的 AI 产品或许是最值得投入的方向之一。本文记录了我用 PydanticAI 搭建一个内容改写 Agent 的完整学习路径，从零到跑通核心逻辑，纯干货。

## 一、Agent 到底是什么？先搞懂本质

很多人把 Agent 想得太玄乎了。其实它的本质很简单：

**Agent = LLM（大语言模型）+ 工具调用（Tool Calling）+ 循环（Loop）**

这个模式在学术界叫 **ReAct**（Reasoning + Acting），也就是"思考 → 执行 → 反思 → 再执行"的迭代过程。

举个具体的例子：我想让 Agent 把一篇技术文章改写成小红书文案。它的工作流是：

1. **思考（Reason）**：分析原文的核心观点、提取关键信息
2. **执行（Act）**：按照小红书的风格完成改写
3. **反思（Observation）**：检查结果是否符合要求，如果不满意就重新执行

这个循环可以执行多次，直到结果达标为止。明白了这个本质，我们就知道 Agent 不是什么遥不可及的黑科技。

## 二、框架选型：为什么最终选了 PydanticAI

市面上的 Agent 框架很多，我调研了三个主流方案：

### LangChain
- **优点**：功能最全，生态最大
- **缺点**：抽象层数太多，隐性学习成本高，调试困难
- **适合场景**：复杂的企业级项目

### OpenAI Agents SDK
- **优点**：API 设计简洁，上手快
- **缺点**：深度绑定 OpenAI 生态
- **适合场景**：纯 OpenAI 技术栈的团队

### PydanticAI（最终选择 ✅）
- **优点**：类型安全、轻量、用 Pydantic Model 定义 result_type
- **适合人群**：Rust / 后端开发者（它的设计哲学和 Rust 的 struct 类型约束如出一辙）
- **核心差异**：你可以用 Python 类型注解精确控制 Agent 的输出结构，这是其他框架做不到的

作为一个 Rust 开发者，我特别喜欢 PydanticAI 用 `BaseModel` 定义输出结构的风格，就像写 Rust 的结构体一样严谨可控。

## 三、环境搭建与第一个 Agent

### 3.1 基础设施

```bash
# 创建项目目录
mkdir content-agent && cd content-agent

# 创建虚拟环境
python3 -m venv .venv
source .venv/bin/activate

# 安装核心依赖
pip install pydantic-ai python-dotenv
```

注意：`pydantic-ai` 的依赖非常多，安装过程可能长达数分钟，请耐心等待。

### 3.2 API Key 配置

创建一个 `.env` 文件存放密钥：

```bash
DEEPSEEK_API_KEY=your_deepseek_api_key_here
```

然后编写配置加载代码：

```python
import os
from dotenv import load_dotenv

load_dotenv()
api_key = os.getenv("DEEPSEEK_API_KEY")
```

### 3.3 核心代码：三行搞定 Agent

```python
from pydantic_ai import Agent
from pydantic_ai.models.openai import OpenAIChatModel
from pydantic_ai.providers.openai import OpenAIProvider

# 1. 定义模型
model = OpenAIChatModel(
    model_name="deepseek-chat",
    provider=OpenAIProvider(
        base_url="https://api.deepseek.com/v1",
        api_key=api_key
    )
)

# 2. 创建 Agent，system_prompt 是灵魂
agent = Agent(
    model=model,
    system_prompt=(
        "你是一个专业的内容改写助手。"
        "用户会输入原创文章，你需要输出三版改写："
        "小红书版（口语化、带emoji）、"
        "公众号版（正式结构化）、"
        "抖音版（短句、高感染力）。"
        "每版需保留原文核心信息。"
    )
)

# 3. 执行任务
result = agent.run_sync("用户输入的文章内容...")
print(result.output)
```

**这里必须强调**：`system_prompt` 是 Agent 的"灵魂"，它定义了 Agent 的身份、行为方式和输出规范。写得好坏直接决定输出的质量，值得花大量时间打磨。

## 四、踩坑记录（血的教训）

### 坑1：PydanticAI 0.8 的 API 变更

文档中使用的 `OpenAIModel` 在 0.8 版本已更名为 `OpenAIChatModel`，且不支持直接通过参数传 `base_url`。必须使用 `Provider` 包装：

```python
# ❌ 旧方式（文档未更新）
model = OpenAIModel(model_name="deepseek-chat", base_url="...")

# ✅ 新方式
model = OpenAIChatModel(
    model_name="deepseek-chat",
    provider=OpenAIProvider(base_url="...")
)
```

### 坑2：结果字段命名

```
# ❌ 错误写法
result.data

# ✅ 正确写法
result.output
```

这个差别在官方文档中没有明确说明，最后是通过阅读源码才确认的。

### 坑3：第三方 API 兼容性问题

最初尝试使用 Kimi Code 的 API，但发现它设置了 **User-Agent 白名单限制**，非官方 SDK 调用会被直接拒绝。最终切换到 DeepSeek 才成功跑通。

**教训**：使用第三方模型提供商的 API 时，优先选择兼容 OpenAI API 标准且无客户端限制的服务商。

## 五、总结

3 行核心代码 + 1 个清晰的 system_prompt，你就可以拥有一个专属的 AI Agent。它的本质是一个"会思考、会调用工具、会自我迭代"的数字员工。
